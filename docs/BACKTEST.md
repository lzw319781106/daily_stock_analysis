# A 股离线回测原型与接口检查

检查基线：`ea3ce3c8034cb553ed2f2ac97fada6ce658dc6c4`（本仓库 main，2026-10-08 读取）。

结论：可以复用日线字段、存储查询和均线计算，**不能把现有每日分析输出直接当作可靠的历史交易回测**。本次新增独立 `src/backtest/`、测试及专用 CI，不修改每日分析、AI、通知、原数据库表或数据源优先级。README 的完整历史分析回测路线图仍未勾选：这里交付的是单股票研究原型。

## 已检查的接口

| 模块 / 接口 | 已核实的行为 | 回测中的处理 |
| --- | --- | --- |
| `BaseFetcher.get_daily_data(code, start_date, end_date, days)` | 返回标准 OHLCV DataFrame；默认最近约 30 个交易日；清洗会删除 close/volume 缺失行 | 复用字段契约，回测入口严格校验、不自动删除或填补历史缺失 |
| `DataFetcherManager.get_daily_data(...)` | 返回 `(DataFrame, source_name)`；自动切换数据源 | 可用于后续历史下载，回测运行不创建 manager、不联网；历史批次应锁定来源和复权口径 |
| `StockDaily` | OHLCV、成交额、技术指标、来源；唯一键 `(code, date)` | 复用表结构读取；缺复权类型、复权锚点、公司行动、停牌、涨跌停及版本元数据 |
| `DatabaseManager.save_daily_data(df, code, source)` | 存在则覆盖同代码同日期记录 | 仅用于隔离的历史库；不把原价和复权价混存，也不覆盖每日分析库 |
| `DatabaseManager.get_data_range(code, start, end)` | 包含两端日期、按日期升序的 StockDaily 列表 | `load_from_storage` 直接复用；命令行另外提供 SQLite 只读查询，无单例初始化或建表 |
| `BaseFetcher._calculate_indicators` | MA5/10/20 使用 `min_periods=1`，四舍五入到两位；量比用前一日窗口 | 不直接使用缓存 MA：暖机不足、精度损失可能改变交易信号 |
| `StockTrendAnalyzer._calculate_mas` | MA5/10/20 为完整窗口、无四舍五入；数据不足 60 行时 MA60 使用 MA20 | 复用 MA5/10/20 的实际计算；不使用 MA60 替代值；自定义窗口用同样的向后 rolling |
| `StockTrendAnalyzer.analyze` / `src/core/pipeline.py` | 主要分析最新一行；管线默认抓最近 30 天，并组合实时/AI信息和推送 | 不作为历史策略函数；回测只接收历史价格和明确的开盘执行权限 |

完整 Python 源码搜索 `backtest / back-test / simulate / simulation / 回测` 未发现已有策略回测引擎。本次不重做每日分析系统。

### 数据源差异

- AkShare：历史请求 `adjust="qfq"`；Efinance：`fqt=1`；Baostock：`adjustflag="2"`，均为前复权。
- Tushare：调用 `daily()`，当前代码未叠加复权因子；成交量乘 100 转股。
- YFinance：`auto_adjust=True`，与原始交易价格不等价。
- Pytdx：`get_security_bars` 从 offset 0 读取最近数据，count 最大 800，然后按请求日期筛选。并非任意历史区间分页下载，不能用它证明长期历史覆盖完整。
- AkShare、Efinance、Pytdx 的历史成交量标准化未见与 Tushare 同样的乘 100 处理；真实接入需要核实各来源原单位，不能仅相信 StockDaily 的“股”注释。
- SQLite 读入时拒绝多个或未知 `data_source`。即使来源单一，仍需检查复权、日期覆盖和单位；原表没有足够元数据自动证明这些条件。

## 本次实现

双均线默认 MA5 / MA20：完整 20 行暖机后，快线高于慢线则目标为持仓，否则目标为空仓。相等时空仓；这是“均线状态持仓”，首次暖机完成已多头时也可以入场。无做空、杠杆或加仓。

执行顺序：

1. 第 t 日开盘，只读取第 t−1 行收盘已生成的目标。
2. 空仓且目标多头时，以开盘价加买入滑点买入可负担的最大整手数量；持仓且目标空仓时，以开盘价减卖出滑点全额卖出。
3. 买入数量先预留佣金和其他费用；默认每手 100 股。同一天只有一次开盘处理，持仓至少跨过一个交易日，符合本原型的 T+1 顺序。
4. 用当天收盘价计算现金加持股市值，再生成当日均线目标。最后一日新信号不在同日成交，也不强制清仓。

费用默认值仅为**可修改的演示假设**：双边佣金万三、单笔最低 5 元、卖方税率万五、双边过户费率十万分之一、单边滑点 5 基点（0.05%）。不宣称适用任何历史日期或券商，实际历史回测应使用分日期费用表。滑点已进入成交价，不再次扣除；另输出其金额供核对。

输出：`input.csv`、`signals.csv`、`trades.csv`、`equity.csv`、`summary.json`。成交明细保留信号日、成交日、原开盘价、成交价、数量、各项费用和交易后现金/持股。摘要保留配置、输入哈希、价格口径及限制。

收益率 = 期末净值 / 初始资金 − 1；最大回撤包含初始资金这个峰值，返回负数。未实现年化收益、夏普和逐笔胜率，避免用合成日历冒充真实交易年。

默认基准是同股票收盘价指数，首日收盘归一化；可以传入外部指数 `date,close` CSV。基准没有费用、滑点或整手约束，属于价格基准，不是与策略资金和成交时点完全匹配的买入持有账户。超额收益是两者累计收益率之差。外部基准必须覆盖全部策略日期，缺失时拒绝运行，不前向/后向填充。

### 成交可行性和复权的边界

零日成交量禁止成交，属于停牌近似：这个字段是整日结果，不证明开盘时已知停牌，也不能证明集合竞价能成交。真实回测应补齐交易日历和**开盘时已知**的停牌状态、涨跌停价及 `can_buy/can_sell`。不能用当天最高价/最低价推断开盘成交许可。受阻后次日使用最新前收盘目标，不保留已过时的订单。

不自动补齐缺失日期；缺行可能是停牌或漏数，当前原型无法区分。存在这些情况时不得把输出视为经过真实交易约束检验的收益。

原始 OHLC 只在已核实无分红送转等公司行动的窗口内用于现金模拟。跨公司行动需要股数/现金账本。复权 OHLC 可用于价格研究，但在整手数量、实际资金和最低费用计算上不能冒充原价。因此非 demo 命令行必须显式选择：

- `unadjusted_no_actions`：用户已经审计该区间无公司行动；程序不会自行核实。
- `adjusted_research`：接受复权价格的研究演示，摘要明确标记现金模拟的局限。

可选 `signal_close` 仅用于均线，而成交/估值仍用 OHLC。该字段和复权因子必须按时点构建，且不能替代公司行动账本。前复权序列可能随未来事件重算；当前防泄漏测试证明固定输入序列下算法的因果性，不证明数据商导出的历史快照本身具备时点一致性。

## 离线运行

在项目根目录运行，无需 API Key，现有项目安装依赖后可直接使用。最小独立环境：

```bash
python -m pip install pandas==2.2.3 numpy==2.2.6 SQLAlchemy==2.0.43 python-dotenv==1.1.1
python -m unittest discover -s tests/backtest -v
python -m src.backtest --demo --output reports/backtest-demo
```

在 Windows PowerShell 中这些命令同样适用。默认输入使用固定随机种子 20261008：180 行合成价格，日期仅为周一至周五，不排除交易所假期。**没有使用真实历史行情，不构成双均线有效性结论。**

## 防未来数据泄漏与验证

18 个离线测试覆盖：

- 每个历史前缀（1 到 90 行）单独回测，信号、成交、净值与完整回测此前部分逐行一致。
- 第 80 行起的未来 OHLC 放大 100 倍，同时污染缓存均线，过去结果保持不变。
- 修改当天收盘、高价、低价，不能改变当天已经依据前收盘信号执行的开盘成交。
- 完整窗口暖机、最后一日信号不成交、禁止同日回转、阻塞买卖和零成交量处理。
- 独立手算成交价、整手数量、佣金下限、买卖费用、滑点和回撤；资金不够一手时不交易。
- 外部基准只用于比较，不改变策略；缺基准日期和重复日期拒绝运行。
- 实际 `StockDaily` 保存/读取往返、直接复用 `get_data_range`，验证 SQLite 只读路径不改变数据库字节；混源和不存在的库拒绝读取。
- 命令行连续运行两次的五个输出文件字节相同；运行期间禁止 socket 连接，不需要真实密钥。
- Financial-API 离线导出映射验证日期、成交量单位、价格口径；字段变化时拒绝猜测。

测试不覆盖数据源自身的复权重算、未提供的历史股票池或未来财务信息。这些需要真实数据和时点快照审计。

## Financial-API 接入

目标项目是 `https://github.com/HiThink-Tech/Financial-API`。本次网络搜索发现了历史行情和公司行动的文档索引，但实际 GitHub 仓库、文档及连接器读取返回 404，无法核实其**当前**认证、参数、响应封装、单位和分页契约。不能把缓存搜索片段当成已经验证的生产接口。当前没有实现或测试真实联网下载器，也不要求提供 Key。

已经实现 `normalize_financial_api_export(records, field_map, volume_unit=..., price_basis=...)`：输入已下载的记录列表，实际字段名由调用方显式映射到现有标准列，成交量明确选择股或手。适配器不假设服务端响应格式；单股票数据经过与 CSV 相同的严格校验，可以直接传入 `run_backtest`。

接入次序：

1. 取得可访问的当前官方文档及一份脱敏历史响应，确认代码后缀、交易日期、OHLC、成交量/成交额单位、复权枚举、复权锚点、分页/行数上限、权限和限流。若响应同时包含多股票，先按代码拆分。
2. 独立下载任务通过环境变量取 Key；校验响应状态、分页边界、日期覆盖，保存原始响应及获取时间。回测仅消费冻结的本地快照。
3. 将实测字段映射传入离线适配器；把 `price_basis` 等元数据保存为侧车 JSON（DataFrame attrs 在 CSV/StockDaily 中不会自动保留）。CLI 仍需显式声明价格口径。
4. 同时下载原始价格、公司行动/复权事件、交易日历和停牌/涨跌停资料。按事件发生时点记账，再用时点一致的信号价格研究。更稳妥的是为回测单独建行情版本表，唯一键含 code/date/source/adjustment/vintage。
5. 另增 `FinancialAPIFetcher(BaseFetcher)` 实现原始下载和标准化，可让每日分析显式选择使用；不要在本次原型中修改自动源优先级。历史下载走独立入口，避免 `DataFetcherManager` 悄悄在批次间切换口径。
